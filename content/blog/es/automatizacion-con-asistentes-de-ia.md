Los asistentes de código IA no reemplazan el criterio de ingeniería: lo aceleran. Cuando automatizo un proceso, sigo un flujo parecido a este:

## 1. Entender el proceso manual antes de automatizarlo

Antes de escribir una sola línea de código, mapeo el proceso actual: qué datos entran, qué pasos se repiten, dónde ocurren los errores humanos. Un asistente de IA puede generar código rápido, pero si el problema no está bien entendido, solo automatiza el caos más rápido.

## 2. Usar el asistente para explorar, no solo para escribir

Uso Claude Code, Copilot o Cursor para explorar varias formas de resolver un problema en minutos en lugar de horas: distintas estructuras de datos, distintas librerías, distintos enfoques. Esto me deja más tiempo para decidir cuál enfoque es el correcto, en vez de escribir todo desde cero.

## 3. Revisar, probar y mantener el control

Todo el código generado con ayuda de IA pasa por revisión: pruebas, lectura línea por línea de la lógica crítica, y ajustes de estilo para que el proyecto siga siendo mantenible a largo plazo. La velocidad no debe sacrificar la confiabilidad.

## 4. Documentar el porqué, no el qué

Cuando el código es claro, no necesita explicar qué hace. Pero si hay una decisión no obvia (una limitación externa, un caso borde), la documento — con o sin ayuda de IA, esa parte siempre requiere criterio humano.
